Credenciales Privadas
01

El Problema de los 7 Días

Supabase asigna contenedores dedicados para cada proyecto PostgreSQL. Para rentabilizar recursos en el nivel gratuito, suspende automáticamente las instancias que acumulen 168 horas (7 días) sin tráfico de red.

⚠️ Consecuencia: Cold starts de 30-45s y posibles timeouts para los primeros usuarios.
02

Mecanismo de Latido Supalive

Supalive envía peticiones GET autenticadas con encabezados apikey y Authorization: Bearer al endpoint PostgREST. El motor valida el token criptográfico y reinicia el contador de inactividad de Supabase a cero.

✅ Margen de Seguridad: Ejecución cada 12h = 14 pings semanales (13 pings de colchón).
03

Arquitectura Zero-Trust

Las credenciales reales residen en GitHub Secrets (cifrado asimétrico Libsodium) y variables de entorno Vercel. El cliente web público nunca recibe las URLs completas ni las claves API reales: todo se procesa en el backend.

🔒 Seguridad: El repositorio y showcase son 100% públicos sin riesgo de fuga.
